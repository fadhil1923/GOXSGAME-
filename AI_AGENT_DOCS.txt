================================================================================
KARENA REPOSITORI INI BERSIFAT PUBLIK DI GITHUB, SETIAP AI AGENT WAJIB MEMATUHI
ATURAN KEAMANAN BERIKUT TANPA PENGECUALIAN:

1. DILARANG KERAS MENG-COMMIT FILE `.env`:
   - File `.env` berisi secret keys (APP_KEY, GEMINI_API_KEY, DB_PASSWORD).
   - Pastikan `.env` selalu berada di dalam `.gitignore`.
   - Gunakan `.env.example` dengan placeholder (misal: `GEMINI_API_KEY=your_gemini_api_key_here`).

2. PEMBACAAN CONFIG YANG AMAN (CONFIG CACHE READY):
   - JANGAN PERNAH memanggil `env('NAMA_KEY')` langsung di Controller/Model/Service.
   - Panggil melalui konfigurasi: `config('services.gemini.api_key')`.
   - Mengapa? Saat `php artisan config:cache` dijalankan di production, pemanggilan `env()` 
     akan selalu mengembalikan `null`!

3. SANITASI DATA PADA COMMIT:
   - Dilarang menyimpan file SQLite lokal yang berisi data riil pengguna (`database/*.sqlite` diabaikan oleh `.gitignore`).
   - Jangan menuliskan token, password hash asli, atau data pribadi siswa ke dalam seeder publik.
   - Gunakan `fake()` / Faker untuk menghasilkan data dummy.

4. HAK AKSES & OTORISASI (ROLE-BASED GUARD):
   - Seluruh rute `/manage/*` wajib diproteksi oleh middleware `role:admin` atau `role:admin,teacher`.
   - Siswa atau guest yang mencoba mengakses rute admin HARUS langsung menerima respons `403 Forbidden`.


ATURAN EMAS DESAIN (GOLDEN RULES):
Estetika GOXSGAME menganut Neo-Brutalisme yang ceria, tegas, dan tebal. 
DILARANG KERAS membuat tampilan yang flat, abu-abu polos, atau tipis tanpa karakter.

1. BORDER & SHADOW
   - Box Utama   : `border-4 border-black rounded-2xl` atau `rounded-3xl`
   - Shadow Keras: `shadow-[4px_4px_0px_#000000]` atau `shadow-[6px_6px_0px_#000000]`
   - Tombol Bouncing:
     * Normal : `translate-x-0 translate-y-0 shadow-[4px_4px_0px_#000]`
     * Hover  : `translate-y-[-2px] shadow-[6px_6px_0px_#000]`
     * Active : `translate-y-[2px] shadow-[0px_0px_0px_#000]`

2. PALET WARNA RESMI
   - Kuning Utama  : `#FFE600` (Accent, Active Nav, Score Banner)
   - Hijau Emerald : `#4ADE80` (Sukses, Play Button, Jawaban Benar)
   - Biru Royal    : `#2563EB` (Primary Brand, Host Banner, Navigasi)
   - Cyan Terang   : `#06B6D4` (Tag Versi, Kartu Info, Master Kelas)
   - Rose / Pink   : `#FB7185` (Danger, Survival Heart, Badge Alert, Jawaban Salah)
   - Ungu Elektrik : `#A855F7` (Kategori Fitur, Mapel, Kotak Saran)
   - Hitam Pekat   : `#000000` (Seluruh Border, Teks Kontras Tinggi)

3. ATURAN KONTRAS MUTLAK (ABSOLUTE CONTRAST RULE)
   > [!CRITICAL]
   > Latar belakang cerah (#FFE600, #4ADE80, #FB7185, #06B6D4, yellow-300, green-400) 
   > HARUS SELALU BERPASANGAN DENGAN TEKS HITAM PEKAT (#000000 !important).
   > JANGAN PERNAH MENARUH TEKS PUTIH DI ATAS WARNA-WARNA INI DALAM KONDISI APAPUN!

4. KONTRAK DARK MODE
   - Root Tag          : `html.dark` (Tersimpan di `localStorage.getItem('goxs_theme')`).
   - Latar Belakang    : Body = `#0F172A`, Kartu/Sidebar = `#1E293B`, Sub-card = `#334155`.
   - Warna Input       : Input teks, textarea, select = Latar `#0F172A`, Teks `#F8FAFC`, Border `#000`.
   - Proteksi Teks     : Di dalam `resources/views/layouts/neo.blade.php`, sudah tersedia CSS global
     yang memaksa elemen berwarna `#FFE600`, `#4ADE80`, `#06B6D4`, `#FB7185` tetap berteks hitam pekat
     bahkan ketika mode dark aktif.

5. PERANGKAP STACKING CONTEXT INPUT
   - Kelas `.neo-input:focus` menggunakan `transform: translateY(3px)`.
   - Efek CSS transform membentuk *new stacking context*, yang dapat menutupi ikon absolute di sampingnya.
   - Solusi baku: Selalu sematkan `.relative > .pointer-events-none { z-index: 10; }` pada wadah ikon input.

9. ALUR BISNIS GAME LOOP & POLLING ENGINE REAL-TIME
================================================================================
Alur Gameplay Realtime (Tanpa WebSocket berat, menggunakan Polling HTTP efisien):
1. [Guru] Memilih Game dari Bank Soal -> Klik "Buka Room Game" -> Menentukan Mode (Classic/Survival/Team).
2. [Sistem] Meng-generate 6-digit `room_code` unik uppercase (contoh: `GOX888`).
3. [Siswa] Buka `/student/join` -> Ketik 6 digit PIN -> Ketik Nama -> Sistem mendeteksi akun auth atau 
   membuat sesi guest otomatis -> Masuk ke Room Lobby.
4. [Guru] Di halaman `/teacher/rooms/{room}` memantau nama siswa yang bergabung -> Klik "MULAI GAME".
5. [Sistem] Membuat record `RoomSession` (`status = 'playing'`, `current_question_index = 0`).
6. [Siswa] Di halaman `/student/room/{room}`, JavaScript Alpine.js mengeksekusi polling interval setiap 2000ms:
   - Endpoint: `GET /student/room/{room}/state`
   - Menerima payload JSON: index soal aktif, sisa waktu, status game, leaderboard sementara.
7. [Siswa] Memilih jawaban -> `POST /student/room/{room}/answer`:
   - Sistem menghitung `time_taken_seconds`.
   - Formula Skor: `max(500, base_points - floor(time_taken * penalty)) * streak_multiplier`.
   - Mode Survival: Jika jawaban salah, `lives_remaining` berkurang 1 (dari total 3 hati).
8. [Power-up 50:50]
   - Siswa menekan tombol powerup -> `POST /student/room/{room}/powerup`
   - Server mengeliminasi 2 opsi yang salah secara acak dan menandai `has_used_5050 = true`.
9. [Guru] Setelah timer habis atau semua menjawab -> Klik "SOAL BERIKUTNYA" (`POST /teacher/rooms/{room}/next`).
10. [Guru] Klik "SELESAIKAN GAME" -> Status menjadi `'finished'` -> Polling siswa mendeteksi perubahan status 
    dan otomatis me-redirect ke `/student/room/{room}/result` untuk melihat podium peringkat.

10. INTEGRASI AI (GOOGLE GEMINI & ROBUST FALLBACK ENGINE)
================================================================================
1. ENV & KUNCI API:
   - Konfigurasi: Dibaca melalui `config('services.gemini.api_key', env('GEMINI_API_KEY'))`.

2. FORMAT OUTPUT JSON STRICT:
   - AI Agent harus menginstruksikan Gemini untuk mengembalikan RAW JSON tanpa markdown wrapper (```json).
   - Format wajib:
     {

       "questions": [
         {
           "question": "Pertanyaan teks?",

     }

   - Jika kuota API habis (HTTP 429), jaringan terputus, atau JSON parsing gagal,
     sistem TIDAK BOLEH menampilkan crash page / Whoops exception ke guru.
   - Sistem wajib menangkap exception (`try-catch`) dan mengembalikan template soal fallback 
     berdasarkan topik kurikulum standar sehingga kegiatan belajar mengajar tetap berlangsung.

11. SISTEM PESAN PENGEMBANGAN (FEEDBACK PENGGUNA KE ADMIN)
================================================================================
Fitur penghubung antara pengguna di lapangan (Guru/Siswa) dengan Administrator sistem:
1. Rute Pengguna:
   - `GET  /feedback` -> `DevelopmentMessageController@create` (Tampil form saran & riwayat pesan pribadi).
   - `POST /feedback` -> `DevelopmentMessageController@store`  (Simpan masukan baru dengan status='pending').
2. Rute Khusus Admin:
   - `GET    /manage/feedback`            -> `Admin\DevelopmentMessageController@index`
   - `PATCH  /manage/feedback/{feedback}` -> `Admin\DevelopmentMessageController@update`
   - `DELETE /manage/feedback/{feedback}` -> `Admin\DevelopmentMessageController@destroy`
3. Parameter Binding Penting:
   - Nama parameter route resource adalah `{feedback}`.
   - Di controller admin, nama variabel parameter wajib: `DevelopmentMessage $feedback`.
4. Siklus Status Pesan:
   `pending` (Menunggu Review) -> `read` (Dibaca) -> `in_progress` (Sedang Diproses) -> `resolved` (Selesai).

   - Gunakan Named Routes (`route('nama.rute')`) di seluruh link dan redirect.
3. KODE FORMATTER (LARAVEL PINT):
   - Setelah selesai mengedit file PHP, jalankan Laravel Pint untuk memastikan format sesuai:
